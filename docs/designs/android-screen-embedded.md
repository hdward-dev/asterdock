# Android 应用内投屏

## 体验

左侧是设备选择、清晰度和无线连接；右侧是应用内画面及返回、主页、多任务、旋转、截图和剪贴板操作。页面沿用 AsterDock 明暗主题。窄窗口改为纵向滚动，不隐藏连接操作。

首次连接在应用内下载并校验 scrcpy 3.3.4 平台包，后续无需启动外部投屏窗口。USB 调试授权仍在手机完成。无线调试支持六位码配对；配对端口和连接端口分别填写。清晰度标记的是画面最长边上限，最高 30 FPS。声音保留在手机播放。

## 实现

- `AndroidBridge`：后台 ADB 命令、超时和设备状态解析。
- `EmbeddedScreenSession`：固定 3.3.4 协议，独立随机设备 socket、ADB 自动分配的本地转发端口、视频/控制双通道。
- 读取带长度和配置标记的视频包。编码配置变化时重新启动后台解码器，使旋转后的画面尺寸与输入坐标一致。
- FFmpeg 8.0.1 通过包内 CLI 解码为 BMP 帧；Avalonia 显示最新帧，UI 队列最多保留一个待显示帧。后续可用原生解码/GPU 渲染降低拷贝开销。
- 坐标按 Uniform 缩放计算，忽略黑边，拖动越界时钳制并在捕获丢失时释放。
- 控制消息按顺序发送；剪贴板按用户按钮请求读取，中文文本通过设备剪贴板粘贴。
- 取消/断线/模块卸载时关闭 socket、终止本会话进程、移除自己的转发端口和设备临时 jar。不停止共享 ADB 服务。
- 平台解码文件随模块分发。Windows ARM64 使用 x64 工具进程兼容模式。macOS 子进程设置局部 dylib 搜索路径，适配分发包中的动态库安装名。
- Linux x64 下载官方 `scrcpy-linux-x86_64` 核心并恢复 scrcpy/ADB 执行权限；模块携带 `ffmpeg/linux-x64`，解码子进程通过局部 `LD_LIBRARY_PATH` 加载随附共享库。固定版本没有 Linux ARM64 官方核心包，安装前会给出架构提示。
- Linux 解码器仍依赖发行版系统库：`libdrm.so.2`、`libva.so.2`、`libva-drm.so.2`、`libvpl.so.2`、`libvdpau.so.1` 和 `libX11.so.6`。最小化系统需先提供这些依赖；可通过 `LD_LIBRARY_PATH=<模块目录>/ffmpeg/linux-x64 ldd <模块目录>/ffmpeg/linux-x64/ffmpeg` 检查缺失项。

## 验证与边界

自动检查位于 `tests/AndroidScreen.Checks`：协议字节、设备状态、黑边与旋转坐标、无效帧、实际 H.264 解码、模拟握手和控制/剪贴板回传、断线与资源清理。

尚需真实 Android 设备验收，以及 Windows 上的运行验证。当前环境没有连接设备。安全窗口/受保护内容、部分厂商的输入限制取决于 Android 系统。当前不实现音频转发、多点触控、游戏按键映射和持续按键组合。

依赖声明见模块的 `THIRD-PARTY-NOTICES.md`。发布者须保留相应许可证和源代码获取信息。

## NTH-AN00 真机兼容修复

2026-09-12 真机握手正常，但硬件编码器输出了 `yuv420p(tv, ycgco/unknown/log316)` 标记，FFmpeg 8 无法转换为 BMP。解码前通过 `setparams` 将 SDR 屏幕捕获色彩元数据归一为 BT.709 后，已收到 736 × 1600 首帧。此路径面向 SDR 投屏，不提供 HDR 色彩还原。

启动/会话失败现在会在画面区显示错误，并保留可展开、可复制的完整诊断，避免仅展示底部的底层 EOF 消息。portrait 测试视频包含同类异常元数据以回归此问题。
